# 模型计价

模型原价由 AI Router 提供，Billing 维护余额和结算事实；支付插件只负责收款。共享的纯计算函数同时供余额结算、费用试算和调用统计使用，不访问其他插件的数据表。

参考 New API 的[倍率设置](https://docs.newapi.pro/zh/docs/guide/console/settings/rate-settings)、[计费价格结构](https://github.com/QuantumNous/new-api/blob/206e0fa5c600127a314a97f88592c067f784f4a6/types/price_data.go)和[文本用量结算](https://github.com/QuantumNous/new-api/blob/206e0fa5c600127a314a97f88592c067f784f4a6/service/text_quota.go)，本项目继续使用 USD 原价与消耗倍率，不使用 New API 的配额单位，也不复制其源码。

表达式设计参考 New API 的[计费表达式](https://github.com/QuantumNous/new-api/blob/main/pkg/billingexpr/expr.md)。解析使用 MIT 授权的 JSEP，计价求值器独立实现，不执行 JavaScript，也不加载用户函数。

## 设置入口

- **渠道与模型 → 模型映射 → 编辑**：按 Token、按次或表达式计价；可选统一单价、上下文阶梯、分段累进、分时及条件定价模板。
- **渠道与模型 → 渠道 → 设置**：渠道消耗倍率。默认 1，可为 0。
- **计费设置**：输出预算策略与默认输出预算（默认 4096 Token）。
- **模型目录 → 详情 → 费用试算**：通过统一路由解析所选渠道，按最终模型价格、入口渠道及分组倍率试算，不调用模型，不产生扣费。
- **用量与账单 / 用户余额与账本 / 全站资金账本**：展开计费明细查看当次用量、单价和倍率快照。

新平台 API Key 绑定一个使用分组；个人密钥绑定自己的个人渠道。`x-pluhub-channel` 只能在当前分组或密钥授权范围内选择渠道，不能通过请求头换组。计费使用入口渠道倍率与分组倍率，流程中的模型重定向和自动路由不替换入口渠道倍率。旧平台渠道绑定通过离线迁移转为同渠道范围、仅原用户可用、倍率为 1 的使用分组；不扩大权限或增加分组费用。管理员权限只控制站点管理，不参与价格计算。

## 费用试算边界

`POST /api/plugins/official.billing/quote` 接收公开 `model`、可选 `channelId` / `groupId` 和归一化 `usage`。登录会话可选择有权访问的分组，API 密钥不能借参数切换分组或越过自身模型范围。同名模型存在多个路由时必须选渠道，避免展示不确定价格。

试算调用 `ai.routing@2` 的 `purpose: "quote"`，与真实调用共用重定向、渠道图、分组及协议检查。可选 `operation` 选择模型支持的端点，省略时使用模型首个端点。可选 `request` 在对话端点按 OpenAI Chat 格式提供消息、工具及流式标志，媒体端点使用对应的 JSON 请求体；条件图缺少请求时返回 `quote_request_required`，当前目录界面没有填写完整请求的入口，因此此类渠道会显示明确错误。自动路由返回 `quote_route_required`，不请求远程决策器、不猜测最终模型。

`context.params`、`context.headers`、`context.at` 用于表达式试算；真实调用仍冻结真实请求的参数、请求头及开始时间。试算不占凭证或并发租约，不预留余额或限流额度，也不证明上游在线或实际 Token 数准确。

## 计算规则

Token 单价统一为 USD / 百万 Token；账本以整数 micro-USD（百万分之一美元）保存。

普通输入 = 总输入 − 缓存读取 − 缓存写入。

基础费用 = 普通输入 × 输入原价 + 总输出 × 输出原价 + 缓存读取 × 读取价 + 普通缓存写入 × 写入价 + 1 小时缓存写入 × 1 小时写入价。

消耗金额 = 基础费用 × 入口渠道消耗倍率 × 使用分组倍率。个人渠道不参与平台钱包扣费。

计算以十进制精确分数完成，最后向上取整一次至 micro-USD。零价格和零倍率保持为零。缓存价格留空时使用输入原价；1 小时写入价格留空时先使用普通写入价。缓存分类是总输入的子集，思考 Token 是总输出的子集，均不重复相加。

按次计费使用 `request` 的 USD / 次价格及上述倍率，不再叠加 Token 费用。仅完整结束的请求自动结算；中断或不完整的调用保留待核对。按 Token 计费但上游未报告完整用量时，不伪造零用量，保留待核对。

阶梯按包含缓存的总输入长度选择，条件为严格大于 `above`，使用命中阶梯计算整次请求，不是分段累进。阈值必须严格递增。阶梯缓存价格未填写时沿用基础缓存价格；基础缓存价也未填写则使用命中阶梯的输入价。

## 表达式计价

表达式模式只读取 `pricing.expression`，输入/输出原价仍可作为模型公开资料维护。渠道与分组倍率在表达式计算后乘入，不把原价与表达式费用叠加。

每个价格分支使用 `tier("名称", 金额)`，可用三元条件嵌套选择档位。支持 `+ - * / %`、比较、`&& || !`、`min/max/abs/ceil/floor/round`，以及整个价格树外的条件乘数。

| 变量或函数                                            | 含义                                                           |
| ----------------------------------------------------- | -------------------------------------------------------------- |
| `len` / `total`                                       | 包含缓存的总输入 / 输入与输出总 Token                          |
| `p` / `c`                                             | 当前档位未单独计价的输入 / 输出 Token                          |
| `cr` / `cc` / `cc1h`                                  | 缓存读取 / 普通缓存写入 / 1 小时缓存写入                       |
| `r`                                                   | 思考 Token，是输出的子集                                       |
| `fixed(0.01)`                                         | 每个完整请求 USD 0.01，替代该档位 Token 费用                   |
| `hour/minute/weekday/month/day/year("Asia/Shanghai")` | 指定 IANA 时区的小时、分钟、星期、月份、日期及年份；星期日为 0 |
| `param("service_tier")` / `header("x-service-tier")`  | 冻结的请求标量，支持点分参数路径                               |
| `has(value, "priority")`                              | 字符串包含判断                                                 |

缓存变量只在命中档位实际单独计价时从 `p` 排除；`cc1h` 单独使用时从 `cc` 排除。思考变量 `r` 单独计价时从 `c` 排除。未使用的子类继续按输入或输出基础价计算，`len` 始终保持完整输入。档位选择条件读取原始归一化用量，避免因价格拆分改变档位。

```text
// 整次请求按上下文档位计价
len <= 200000
  ? tier("标准", p * 3 + c * 15 + cr * 0.3)
  : tier("长上下文", p * 6 + c * 22.5 + cr * 0.6)

// 分段累进
tier("累进", min(p, 100000) * 2 + max(p - 100000, 0) * 1.5 + c * 8)

// 工作日高峰；其余时间低谷价格
weekday("Asia/Shanghai") >= 1 && weekday("Asia/Shanghai") <= 5
  && hour("Asia/Shanghai") >= 8 && hour("Asia/Shanghai") < 20
  ? tier("高峰", p * 2 + c * 8)
  : tier("低谷", p * 1.6 + c * 6.4)

// 按输入长度选择按次或按 Token 价格
len <= 32000 ? tier("短请求", fixed(0.01)) : tier("长请求", p * 2 + c * 8)

// 请求条件乘数
tier("标准", p * 2 + c * 8) * (has(header("x-service-tier"), "priority") ? 2 : 1)
```

以上注释用于文档说明，保存时只填写所选表达式。不提供 `|||when` 简写、对象访问、任意函数或尚未归一化的图片/音频/视频用量变量；不支持的语法在保存时拒绝。固定按次价格不能与 Token 费用相加或直接乘 Token 数；不同档位可以分别使用按次和按 Token 价格。

请求开始时冻结时间及标量事实，自动路由比较候选价格时使用同一时间。预留对估计用量区间覆盖所有可能档位、缓存组成及条件乘数，按保守上界占用额度；结算使用实际用量和原快照。跨时段、夏令时切换或配置更新不重新读取系统时钟。无法得到有限上界的表达式在上游调用前拒绝；求值失败、负金额或缺少所需用量保留待核对，不默认为免费。

公开目录按档位展示可解析的原价和扣费价，复杂规则展示原表达式；列表标为动态定价，不伪造统一单价。费用试算支持指定计价时间、参数与请求头。快照只保存引用到的标量，不保存提示词、工具定义、认证 Header、Cookie 或密钥。

## 预留与快照

Admission 阶段记录模型原价、阶梯及渠道消耗倍率快照，同时记录本次输出预算。输入按 UTF-8 字节和消息结构估算，预留选择配置中最贵的缓存和阶梯单价；按次计费预留固定金额。

`outputBudgetMode` 支持三种策略，默认 `automatic`：

- `automatic`：支持输出上限的上游使用同一个最终上限进行预留和实际调用。优先使用渠道流程图处理后的客户端上限；未指定时应用 `reserveOutputTokens`（默认 4096）。Codex SIWC 支持该上限；Codex CLI 不支持，会先移除客户端/流程中的输出上限与 temperature，再使用站点默认输出 Token 数估算预留，并在调用记录中标明估算模式。
- `bounded`：强制应用输出上限。Codex CLI 等无法施加上限的上游，按 Token 计费时在预留及调用前返回 `output_budget_unsupported`；固定按次价格可以继续使用，费用预留为已知的单次金额。
- `estimate`：不为缺少上限的请求注入默认参数，只预留估算额度；支持输出上限的上游继续传递客户端或渠道已经指定的上限；Codex CLI 的这些参数仍被忽略。

`reserveOutputTokens` 保留原配置名称。自动或强制模式下有效范围为 1–1,000,000；估算模式保留原来的 1–100,000,000 范围。渠道流程图的输出上限优先于站点默认值，不放大客户端已明确指定的上限。Anthropic / Gemini 的显式思考预算在缺省输出上限时额外保留 1024 Token 的回答空间；上游归一化输出用量已经包含思考 Token，结算不重复累加。Anthropic 的思考预算必须小于显式输出上限，冲突在预留之前拒绝。

请求预留的 `budget` 保存输入估计、输出预留量、实际发送上限、来源和估算/约束方式。调用详情使用同一快照展示输出上限或估算方式。价格、模式和默认上限在请求准入后修改，不影响已准入的请求。

上游返回的权威输出用量超过已发送上限时，以 `upstream_budget_exceeded` 结束请求；流开始后通过流式错误事件报告，预留进入待核对，不自动追加扣款。明确的生成前拒绝会释放预留；已派发但结果不明、缺失用量、未完整结束或取消的请求继续保留待核对；预算快照在重启后保留。

Finalize 根据上游权威用量及保留的价格快照结算，多退少补；系统价格在请求执行期间改变，也不改变这次请求的单价。输出上限并非整笔请求的绝对金额保证：输入用量仍是估算，估算模式的输出也不受默认上限约束，实际成本超过估算时仍可能产生负余额；后续调用继续检查可用余额。管理员核对待处理请求时须记录原因；重启后未完成预留继续保留待核对，结算按请求 ID 幂等。

重定向和自动路由按最终执行模型、物理渠道计价。个人自带密钥渠道仍由上游收费，不扣平台余额。试算只针对所选公开模型的静态价格，动态路由的最终执行价格由实际路由结果决定。

当前覆盖文本、Embeddings 输入 Token、缓存、思考用量、按次、上下文阶梯、表达式、分段累进、分时与请求条件计价。

`pricing.webSearch` 为每次已完成搜索的 USD 原价，在 Token、按次或表达式金额之外追加，再统一应用渠道倍率并向上舍入到微美元。`usage.webSearch`、价格及明细行一并保存；重复 SSE / 最终快照不会重复计数。未执行搜索不计工具费，失败或中断继续进入待核对。未设置此价格不追加费用；原生 Chat 无法提供工具次数，配置独立搜索价时在调用前拒绝，需使用 Responses / Codex。按 `max_tool_calls` 预留搜索费，缺省为 3 次估算，实际完成次数用于结算。Codex CLI 不支持工具次数上限，带该参数的请求会在预留前拒绝；省略后使用估算策略。

图片与音频使用 `mode: "request"` 或固定金额表达式。请求条件（例如图片数量、尺寸与质量）可通过已有表达式事实快照参与选价；固定单次价格按一次请求收取，不自动推导每张或每分钟费用。例如每次原价 $0.04、渠道倍率 0.2，完成后扣 $0.008（8000 微美元）。没有可核实的 Token 用量时，固定价格不伪造 Token 计数；媒体 Token 和音频时长的细分类计量尚未提供。视频和其他托管工具仍需独立的协议及计量契约。

历史账单金额保持原值。迁移将旧用户/分组因子合并到快照的单一倍率，删除旧字段及旧分组表；运行时不再保留历史倍率分支，也不重新扣取历史费用。

使用分组的倍率与渠道倍率合并后写入 `RequestPricing.multiplier`；`serviceGroup` 保存请求当时的分组说明，详见 [使用分组与调用范围](COMMERCIAL.md#使用分组与调用范围)。

## 待核账与明确拒绝

「预留」暂时占用可用余额，「扣费」是资金账本已记账，两者不同。完整结束且用量可信时自动结算；缺少用量、输出截断、客户端取消、网络结果不明、超出输出上限或重启未完成结算时保留预留并给出核对原因。不能把未知用量当成零用量，也不能仅凭 HTTP 200 判断流式请求成功。

上游明确返回生成前的认证、参数、模型或限额拒绝时释放预留；本地编码阶段拒绝也不产生模型费用。服务错误和传输中断不能一律视为未生成。新的判断只依据实际调用阶段和拒绝证据，不凭旧日志的通用错误代码追溯修改历史资金记录。

管理员在「计费设置 → 待核对请求」核对上游账单或权威用量，填实际费用并记录依据；填 0 释放预留。状态、说明、预留和实扣金额由 Billing 提供给调用记录，观测插件不自行决定退款或补扣。
