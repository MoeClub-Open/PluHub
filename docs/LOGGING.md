# 日志

管理后台「系统管理 → 运行日志」查询宿主、插件及 HTTP 请求日志。调用记录继续由 Observability 插件提供；管理员可从调用详情跳转到相同请求 ID 的运行日志。

## 记录范围

- 运行日志：插件启停和启动异常、Process 插件输出、请求完成、异常、取消，以及流中断。
- 请求字段：服务端生成的请求 ID、执行图版本、方法、路径、状态、错误代码和持续时间。请求 ID 与响应头 `x-pluhub-request-id`、调用记录 ID 相同。
- 日志在响应流结束或取消后记录最终结果。HTTP 200 的流也可能失败，应同时查看错误代码。取消记为警告。
- 健康检查、根页面、扩展静态资源及日志查询的成功请求不记录，避免刷屏。日志查询的认证失败仍会记录警告。
- 不采集请求和响应正文、提示词、请求头或 URL 查询参数。插件自由文本会移除已知环境变量密钥、授权值、常见密钥字段、`sk-` / `ph_` 密钥、PEM 私钥、URL 凭据和查询参数；脱敏后再截断，单条消息最多 2048 字符。未知格式的秘密仍需插件作者避免写入日志。

## 持久化和权限

运行日志保存于宿主数据目录 `runtime-logs.sqlite`，同时以 JSON 行写入 stderr，供 Docker 日志收集。SQLite 保留 30 天、最多 50,000 条；启动、查询、每 100 次写入和每分钟清理过期数据，写入时限制总条数。删除的数据页由 SQLite 复用，文件不会随历史请求无限增长。

`GET /api/host/logs` 仅管理员控制台会话可访问；普通用户和 API Key 均不能查询。支持 `level=info|warn|error`、`plugin`、`requestId`、`q`、毫秒时间戳 `from/to`、`limit=1..100`、`offset`。响应包含 `items/total` 和保留策略，以及当前进程的 `dropped/failures`。SQL 参数全部绑定，搜索关键字按字面匹配。

存储故障会在 stderr 提示、增加计数并暂缓重试 30 秒；业务请求继续执行。故障期间的日志无法补写到 SQLite，应结合容器日志检查。查询不可用时返回 503。退出前先排空请求，再关闭数据库和清理定时器。

Observability 调用日志可配置 `retentionDays`（默认 30 天）和 `maxRows`（默认 100,000，范围 1,000–1,000,000），每分钟及写入时清理。请求列表和汇总支持 `requestId/upstream/errorCode` 精确筛选，普通用户始终只能查询自己的记录。管理操作审计独立保存，不与运行日志合并。

管理审计按时间、结果、方法、操作人、目标用户或请求 ID 组合查询，筛选条件在地址中保留；可由审计请求 ID 跳转到对应运行日志。审计故障和超过五分钟未完成的记录在系统状态中显示，写入前留痕及结果未能记录时的处理规则见 [管理功能](ADMINISTRATION.md)。

调用记录保存经过校验的用量和计价快照，详情显示请求发生时的费用估算，实际扣款以资金账本为准。写入失败不会破坏上游响应或独立的计费结算；管理员通过 `/api/plugins/official.observability/status` 查看 `available/dropped/failures`，系统状态页在存储异常时告警。查询不可用时返回 503，丢失记录不自动补写。

## 前台请求记录与企业权限

前台「调用记录」支持模型、请求 ID、状态、入口协议、渠道 ID、密钥 ID、错误代码、自定义时间范围和用户筛选。筛选同时应用于列表、用量、成本与图表；「仅自己」可进一步缩小范围。

筛选保存在页面地址中，刷新后保留。`GET /api/plugins/official.observability/requests/export` 按相同筛选和权限导出 CSV，最多 10,000 条，超出时要求缩小范围；同一用户每 5 秒允许一次导出。CSV 带 UTF-8 BOM，并防止单元格公式注入。

- 普通用户和子账号仅能查看自己的请求；企业主账号的控制台会话可查看自身及直属子账号的请求；管理员会话可查看全站。
- Users 插件维护 `accountType=personal|enterprise` 和 `parentId`，并通过 `users.log-scope@1` 提供允许查看的用户范围。Observability 不直接读取 Users 的数据库。
- 管理员在「用户管理 → 用户详情 → 账号归属」指定企业主账号或所属企业；变更进入管理审计。子账号不能修改归属、查看同级账号或其他企业。角色与企业归属分开管理，不引入工作空间。
- 首版为单层归属；企业主账号不能同时成为子账号，有子账号的企业必须先移交子账号再转换为个人账号。子账号不能直接授予管理员角色。
- 每次请求重新校验归属，不缓存授权结果。关系转移后，旧企业立即失去该子账号历史日志的查看权，新企业取得查看权。API Key 仍只能读取其所属用户的记录。
- `GET /api/plugins/official.observability/log-scope` 只返回当前身份可见的用户名称与 ID。`requests` 与 `summary` 使用同一权限约束；指定越权 `userId` 返回 403。
- 没有 Users 范围能力时，Observability 保持个人隔离和现有管理员查询功能，不自动扩大普通用户范围。

## 验证

运行 `pnpm build:all` 后执行 `pnpm exec vitest run tests/logging.test.ts tests/gateway-product.test.ts`。覆盖敏感信息脱敏、SQLite 重启持久化、容量和闲置清理、管理员隔离、流失败和取消、存储故障及 Process 日志级别。
