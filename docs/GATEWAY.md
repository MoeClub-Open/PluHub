# AI 中转网关功能迭代

网页使用流程：登录账号 → 在模型目录选择可用模型 → Playground 流式调用 → 查看请求记录与总览。接入外部客户端时创建个人 API Key。

## 功能入口

| 页面 | 功能 | 可访问用户 |
| --- | --- | --- |
| 总览 | 24 小时 / 7 天 / 30 天调用量、Token、首 Token 延迟、成本估算、模型排行 | 管理员查看全局；普通用户查看自己 |
| 模型目录 | 搜索、供应商筛选、价格排序、接入示例、跳转试用 | 登录用户；API Key 查询仅返回允许的模型 |
| Playground | 模型选择、多轮文本对话、系统提示词、Temperature、流式输出及停止 | 使用当前登录会话，无需填写 API Key；计入当前账号用量与费用 |
| 调用记录 | 模型、状态及时间筛选、分页、请求 ID、延迟、用量、错误代码 | 管理员查看全局；普通用户查看自己 |
| API 密钥 | 创建、一次展示、撤销、模型范围、有效期、每分钟请求上限、最近使用 | 本人控制台会话 |
| 渠道与路由 | 渠道及模型的表单增删改、启停、模型展示信息、配置价格、显式请求测试、可选 JSON 编辑 | 管理员会话 |
| 用户 / 插件管理 | 用户管理、安装及启停插件 | 管理员会话 |

界面支持明暗主题、键盘焦点、原生模态对话框和移动端侧栏。所有统计来自实际经过网关的请求；没有请求时展示空状态。

全站用户安全、Key 撤销、个人渠道封禁、订单订阅、资金账本和管理操作记录的操作及权限边界见 [管理功能](ADMINISTRATION.md)。

管理员的「系统设置」提供分类总览和设置搜索，进入后侧栏切换为配置导航，可随时返回控制台。渠道执行功能统一在流程图内配置，限流、TPS 和自动路由不单独占用页面或页签；全局限制从请求入口节点打开，共享策略从自动路由节点打开。「支付与商业」包含支付方式、商品订阅和计费设置；余额调整及用户权限组在用户管理中。Stripe、易支付及后续适配器在「支付方式」页内搜索和配置，适配器停止后从列表移除。「安全与验证」通过一个「登录与验证」入口管理登录注册、邮件、Turnstile 和 Passkey 策略。插件管理与系统状态有固定管理员入口。

控制台将工具与账号分组。钱包只占一个侧栏入口，页内切换余额账单、充值订阅；订单和订阅分别按需查看。支付选择只显示实际启用的方式，并按商品币种筛选；确认购买后才创建订单，未支付订单可继续付款。取消续订前说明本期权益结束时间，服务端重复取消不重复调用支付平台。管理员余额调整和费用核对输入 USD，精确转换为整数微美元，后台 API 和账本单位保持不变。账号设置通过底部账号入口进入，原有页面地址继续可用。

渠道列表可按名称、ID、地址及已映射模型搜索，组合状态与协议筛选，并按 10/20/50 条分页。选择可跨页和筛选保留，批量操作会显示不在当前页的选中数量；批量停用需要确认影响范围。启停只调整所选渠道，不改变模型映射的独立启停状态，也不触发上游测试。仅当渠道凭证发生变化时才同步相关适配器的密钥引用，保留手动授权和其他插件配置。

## 站点品牌与外观

管理员进入「系统设置 → 站点与品牌 → 品牌与外观」，配置站点名称、简介、Logo、浏览器图标、主题色、登录标题/说明、页脚文案、官网/服务条款/隐私链接和支持邮箱。表单提供实时预览、放弃草稿和保存状态；未保存时刷新或关闭页面会触发浏览器提示。Logo 和图标可上传不超过 64 KiB 的 PNG/JPEG/WebP，或填写 HTTPS / 站内绝对路径；不支持 SVG、任意 HTML、脚本 URL 和含凭证的 URL。链接指向已有页面，不生成政策正文。

配置保存在 `official.console` 的 `config.branding`，通过已有 `http.route` 授权提供公开的 `GET /console/branding`。只有声明的品牌字段会公开；管理写入仍走受管理员保护的配置 API。Console 使用配置快照热更新，不增加安装权限，重启后保留。服务端 HTML 和初始化 JSON 均转义；主题色自动调整明暗主题中的文字及按钮对比度。

~~~json
{
  "branding": {
    "name": "我的 AI 网关",
    "description": "一个入口，连接所有模型。",
    "accentColor": "#635bff",
    "logoUrl": "https://example.com/logo.png",
    "faviconUrl": "https://example.com/icon.png",
    "loginTitle": "连接所有模型，\n从这里开始。",
    "supportEmail": "support@example.com"
  }
}
~~~

品牌配置仅覆盖控制台、登录页和站点页脚；不改动公开模型别名、API 协议、邮件模板或支付商托管页面。顶部搜索与 `Ctrl/Cmd+K` 支持查找当前用户可访问的页面和设置，不提供用户数据或订单全文搜索。

## 渠道和模型

在启动宿主前设置上游密钥环境变量。添加渠道时填写协议、Base URL 和 `env:NAME` 引用，保存时自动更新相应上游适配器的引用授权。密钥明文不会写入路由配置。

添加模型映射时指定公开模型 ID、渠道和实际模型 ID；可选填写显示名称、供应商、描述、上下文长度以及输入/输出每百万 Token 的 USD 价格。显示信息和价格由管理员维护，不自动抓取服务商数据。停用渠道或模型后，新请求不再使用它，模型也从目录中隐藏。

“发送测试请求”使用该渠道的第一个已配置模型，发送 `Reply OK`、默认 256 个输出 Token 预算的非流式请求，超时 30 秒。API 可通过 `maxTokens` 指定 32–1024 的预算。必须收到非空正文和正常结束才通过，空回答和预算截断不会报成功。测试可能产生用量，不会自动周期执行；结果是当次测试结果，不代表持续健康状态。虚拟渠道通过工作流预览或公开模型完整调用验证。

## 密钥与观测语义

- 模型限制使用公开模型 ID 的精确匹配，空列表表示全部模型。过期、撤销及用户禁用会影响后续认证。
- 每分钟上限以单个 Key、单节点、自然分钟计数，重启清零；它不是用户总配额或财务预算。
- API Key 用于模型调用，不继承管理员系统权限，也不能创建新 Key 或修改密码。凭证管理必须使用登录会话。
- Observability 将请求元数据写入独立 SQLite，默认保留 30 天，可通过 `retentionDays` 配置为 1–365 天。默认不保存提示词、回答正文和认证头。
- 每个请求最终记录一次；成功、失败和客户端取消分开统计。成功率为成功数 /（成功数 + 失败数），取消不计入失败。
- 延迟分为总耗时与首次文本/工具输出时间；Playground 展示的是浏览器观察到的首字延迟，两者测量位置不同。
- 上游未返回有效用量时记录未知；未配置输入/输出价格或缺少用量时不计算成本。成本按请求开始时绑定的价格快照估算，不用于钱包扣费、结算或可靠财务记账。
- 流式响应中途失败时，HTTP 可能已返回 200，需查看最终状态及错误代码。返回头 `x-pluhub-request-id` 可用于定位日志，包括非流式错误响应。

## 本地演示

~~~sh
pnpm bootstrap
pnpm build:all
pnpm demo
~~~

访问 `http://127.0.0.1:18181`，使用终端输出的 `admin` 密码。演示上游运行于本机 `18182`，使用固定演示文本和用量，不调用付费接口；配置、数据库与正式配置隔离。可设置 `PLUHUB_DEMO_PASSWORD`、`PLUHUB_DEMO_PORT` 和 `PLUHUB_DEMO_UPSTREAM_PORT`。每次启动会重置演示路由与管理员密码，数据库保留。

正式运行仍使用 README 的 `init / bootstrap-admin / start` 流程。

## 从上一版配置升级

停止宿主，先备份配置及数据目录。Auth 的 SQLite v1 数据会自动迁移并保留已有密码、会话及 Key；已有 Key 默认无模型及频率限制、不过期，但不再具有管理员管理权限。

在 Auth 的配置条目 `grants` 中增加 `hooks.register`。另外安装 `model-catalog`、`observability`、`playground`、`leaderboard`，分别授权其 Manifest 声明的权限。新的 `init` 已包含全部 34 个插件；旧配置不会在普通启动时自动增加插件或授权。

## 参考与当前边界

功能组件参考 [AxonHub](https://github.com/looplj/axonhub) 的渠道、模型与观测组织，以及 [New API](https://github.com/QuantumNous/new-api) 的渠道和访问凭证管理。界面参考 [OpenRouter 模型目录](https://openrouter.ai/models)、[OrcaRouter](https://www.orcarouter.ai/) 的模型浏览和调用入口，以及 [B.AI](https://b.ai/) 的留白和输入界面。

已支持静态绑定、自动模型/思考路由、隐式/显式重定向及可视化渠道组合，见 [渠道工作流](WORKFLOWS.md)。不自动跨上游重试；账号池和多节点调度继续后续建设。钱包、支付、BYOK 和订阅上游见 [商业能力](COMMERCIAL.md)。New API 已通过 16 次真实生成/工具往返，范围见 [联调说明](LIVE_TESTING.md)；其他服务商及生产环境仍需分别验收。Docker 部署见 [容器指南](DOCKER.md)。
