# 管理功能与操作边界

管理员使用控制台会话管理系统；管理员的 API Key 仅用于模型调用，不能操作管理接口。普通用户仅能管理自己的账号、Key、渠道、订单和余额明细。

## 管理入口

| 入口 | 可执行操作 |
| --- | --- |
| 用户管理 → 用户详情 | 在「账号与权限」管理角色及安全状态、重置密码、撤销会话和验证方式；在「余额与账本」查看该用户余额、预留与资金明细，记录带原因的余额调整；可跳转该用户的 Key、渠道和订单 |
| 设置 → 安全与验证 → 访问密钥管理 | 按用户、名称、前缀和状态查询全站 Key，撤销指定 Key；仅返回安全元数据 |
| 设置 → 渠道与路由 → 用户渠道管理 | 查询用户自建/预设渠道，管理员封禁或解除；用户自行启用不能覆盖管理员封禁 |
| 设置 → 支付与商业 → 商品与订阅 | 配置商品和结算地址，查询全站订单、订阅、退款与争议及钱包投递，停止 Stripe 自动续订，重新核对支付事实并重试账务投递 |
| 设置 → 支付与商业 → 计费设置 | 启停全站预付计费、查询全站资金账本、核对未知用量的预留；用户余额调整统一从用户详情执行 |
| 设置 → 系统管理 | 按名称、用途和 ID 查找插件，安装/启停及为支持的插件在线升级，查看系统状态和管理操作记录 |

品牌与门户、邮件/Turnstile/Passkey 策略、支付适配器、路由和流量策略沿用聚合设置入口。渠道均通过流程图组合功能。

## 敏感操作

重置密码/验证方式、撤销会话或 Key、封禁渠道、调账、入账重试及管理员取消续订需要最近五分钟内登录或重新确认身份。控制台可用密码及已启用的 TOTP/恢复码确认；Passkey 用户可重新登录。写请求同时验证会话、权限和 CSRF。

重置验证方式前要求用户已设置密码，并输入目标用户名；操作会注销其全部会话。最后一个启用的管理员不能降级或禁用，用户不能在管理列表禁用自己。调账先展示目标用户、增减金额和原因，确认后使用幂等 ID 入账。

管理渠道封禁独立于用户的 enabled 状态；封禁影响后续渠道选择和凭证解析。撤销 Key、禁用用户、角色变更影响后续请求；已经开始的流不会因此追溯改写。

## 操作记录与持久化

控制面将管理员 `/api/` 写操作保存在宿主数据目录的 `admin-audit.sqlite`，保留 90 天。记录包含操作人、时间、路径、目标资源/用户、结果、错误码及业务提供的操作原因。记录在执行前创建，执行后按请求 ID 更新；开始记录失败时拒绝操作，结束记录失败时保留待核查记录并写宿主日志。查询支持操作人、目标用户、请求 ID、方法、成功 / 失败 / 待核查及起止毫秒时间，条件取交集；路径或资源搜索按字面匹配 `%`、`_` 和反斜杠，时间边界包含端点。无效条件返回 400。

后台「管理操作记录」使用既有页面提供筛选，条件保存在地址中并在刷新后恢复；较少使用的时间、方法和请求 ID 折叠到更多筛选。请求 ID 可跳转到运行日志。读取失败时不展示上次成功查询的旧结果。审计列表响应禁止缓存，查询和系统状态检查也会清理到期记录。

`GET /api/host/status` 的 `audit` 返回 `available`、`failures`、`writeFailures`、`unresolved` 和 `retentionDays`。计数属于当前进程；`unresolved` 为超过五分钟仍无最终结果的记录数，存储不可用时为 `null`。审计不可用、出现写入失败或存在此类记录时，宿主状态显示 `degraded`，系统状态页提示检查。故障统一返回 503 `audit_unavailable`，不暴露数据库路径或 SQL 错误。存储恢复后可继续操作，既有待核查记录不自动推定成功。

不保存请求正文、密码、认证头、完整 Key 和支付密钥。该记录用于单机运维追溯，不提供防篡改外部归档保证；应随数据卷备份。

管理审计自由文本与运行日志共用密钥脱敏器，写入前先脱敏再截断；读取历史条目时也脱敏，不重写历史数据库原文。旧卷中可能已经存在的敏感文字仍须按备份和留存策略处理，界面脱敏不等同于物理删除。账号登录及验证方式变更由 Auth 安全历史记录，同一审计入口提供「账号安全」页签，权限、保留期和故障语义见 [账号安全](IDENTITY.md)。

插件配置保存失败会恢复启停状态，安装失败会清理本次注册和文件。提供当前管理身份、Listener 或 Console 的活动插件不允许经 Web 控制面停用，以免锁死管理入口；本地 CLI 仍可在维护窗口操作。

“更新方式”分别标明配置是否即时生效、代码是否支持在线升级。首批 11 个无持久状态的协议入口、标准上游、模型目录、模型试用和协议转换插件声明支持在线升级；其余插件保持重启升级。更新通过独立目录和执行图切换完成，现有授权不扩大，操作原因进入管理记录；规则见 [插件 API](PLUGIN_API.md)。

Users、Auth、BYOK、Billing、Commerce 各自维护数据，通过公开 Capability 协作。各插件按迁移版本管理自己的 SQLite Schema；升级前应停机备份并在隔离卷验证，回滚必须同时恢复数据库和匹配镜像。

## 首期保留边界

角色固定为管理员和普通用户，尚无自定义 RBAC/组织租户、账号冒充或管理员查看用户完整凭证。订阅取消仅停止续费，本期权益保留；不提供手工标记付款成功、绕过支付验签、自动退款/税务及争议处理。资金入账重试不重新收款。退款需在支付平台按实际业务处理并核对账本。
