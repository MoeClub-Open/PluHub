# 单节点运维

本文适用于 Docker Compose 部署。以下命令在部署目录执行，假定项目名为 `pluhub`、服务名为 `gateway`、本机端口为 `18100`；其他部署应替换对应参数。部署目录维护 `compose.yaml`、受保护的 `.env`、发布目录和备份目录，凭证不得进入源码仓库。

## 日常检查

```sh
docker compose -p pluhub ps
docker compose -p pluhub logs --tail 100 gateway
curl --fail http://127.0.0.1:18100/healthz
curl --fail http://127.0.0.1:18100/readyz
```

检查容器重启次数、退出码、磁盘余量、内存、插件失败和结构化错误。`healthz` 判断进程存活，`readyz` 判断本地认证及路由是否能接收请求；二者不能证明上游、邮件或付款正常。

系统状态页展示数据所在文件系统容量，不返回真实路径。可用空间不足 1 GiB 或低于 10% 时提示检查，并将管理状态标为 `degraded`；读取失败也会提示。该提示不自动停用业务，不代替网关就绪检查。请求限流和部分租约保存在进程内存，重启会清空相应状态。

对照 [实现范围](IMPLEMENTATION.md) 评估监测缺口。当前没有通用监测导出和告警通知闭环，应由部署环境补齐可用性、容量、备份和支付异常的巡检与通知。

## HTTPS 与访问来源

配置域名和证书，反代至本机端口，参考 `nginx.conf.example` 保留 WebSocket 升级并关闭 SSE 缓冲。Listener 的 `publicOrigin` 与 Auth 的 `secureCookie` 必须匹配外部 HTTPS 入口；已有实例以数据卷配置为准，修改命令见 [Docker 部署](DOCKER.md)。

`trustedProxies` 仅包含已确认的直接代理及必要上级代理地址。Cloudflare 网段以官方 [IPv4](https://www.cloudflare.com/ips-v4)、[IPv6](https://www.cloudflare.com/ips-v6) 清单为准。不能信任所有公网或整个容器网段，否则伪造来源会影响登录保护和配额判断。

通过外部域名检查登录 Cookie、管理写入的来源保护、密钥权限、静态资源、流式首事件/结束/取消和适配器回调。通过实际开放入口检查伪造来源头是否被忽略；就绪检查不能代替这些检查。

## 升级与离线迁移

业务凭据使用宿主加密存储。升级会在插件启动前导入旧环境变量引用，随后应从 Compose 和环境文件移除相应密钥项；备份需包含数据目录中的 `secrets.key` 与 `secrets.json`。具体流程见 [凭据与参数](SECRETS.md)。

升级使用固定镜像版本和匹配的三仓源码，不使用浮动标签作为回滚依据。构建与常规检查不调用付费生成、邮件或支付服务。

1. 备份 `.env`、Compose 配置和完整数据，保存当前镜像标识。涉及数据迁移的候选版本，先在独立恢复卷验证。
2. 停止业务，确保没有其他宿主写入数据。Docker 入口在持有独占锁时执行配置迁移，再同步随镜像提供的插件。
3. 切换 `PLUHUB_IMAGE`，运行 `docker compose -p pluhub up -d --no-build`。
4. 检查就绪状态、插件活动状态、账号登录、目录与密钥使用范围，以及受影响的资金或业务记录。

迁移会把旧渠道连接和功能移入流程图，移除已退役插件及能力绑定，把输出节拍绑定迁到 `@2`，并为标准 AI 入口启用已安装的请求限流插件。若缺少该插件，应先安装，不能绕过限流依赖启动。

旧平台渠道密钥迁入只允许原用户、原渠道且倍率为 1 的受限分组；原模型限制、有效期和请求上限保持。自动生成的分组使用真实渠道名称展示，管理员从独立「使用分组」页面维护；改名不改变绑定。个人密钥仍绑定个人渠道。相同渠道范围合并到同一迁移分组，不扩大到默认全部渠道。混合绑定平台和个人渠道的旧密钥必须先拆成两把密钥。Auth 数据库尚无分组字段的更早版本，应先升级至支持使用分组的版本。

源码部署使用以下离线入口，省略 `--write` 只预览；执行前停止宿主并备份。Docker 已自动执行相同迁移，不需要重复操作。

```sh
bun scripts/migrate-plugin-boundaries.ts /path/pluhub.json
bun scripts/migrate-plugin-boundaries.ts /path/pluhub.json --write
```

BYOK 的标准入口测试需要 `http.dispatch`，离线迁移为原有官方插件补充该授权；个人组装路线仍逐次检查真实分组权限。配置变化前生成原配置副本；密钥变化前生成数据库副本。先写分组配置再更新密钥，重复执行不会重复建组或扩大权限；中断后可继续运行。迁移只用于升级，不作为在线业务插件读取其他数据库的通道。

## 备份与恢复

加密备份使用 `python3 -B deploy/backup.py create-offline`，独立恢复检查使用 `check`；维护窗口由 `deploy/backup-schedule.py configure` 设置，详细参数见 [Docker 部署](DOCKER.md)。新站不自动启用定时停机备份或异地上传。

备份必须包含配置、所有插件数据库、加密密钥及匹配的镜像信息。离线备份持独占数据锁，不能直接复制运行中的 SQLite 文件。加密归档和解密密钥分别保管，定期在新空卷恢复检查；只有备份文件存在不能证明可恢复。

回滚先停止新版本，恢复与旧镜像匹配的数据和部署配置，再启动旧镜像。数据库迁移并非自动可逆，不能只换镜像。存在支付回调、待结算请求或已对外确认的交易时，先核对停机窗口内的资金事实，避免恢复旧快照丢失已确认交易。

## 故障定位与保留

根据响应头 `x-pluhub-request-id` 对照调用记录、运行日志及资金账本。流式请求的 HTTP 200 不代表最终成功；缺少用量或中断请求可能进入待核对。不要把人工重试和自动退款等同于故障修复。

磁盘清理只处理已确认不再使用的本项目镜像和源码归档，保留当前镜像、回滚镜像及匹配备份。先核对容器引用和保留清单，不执行影响其他应用或数据卷的全局清理。

远程源码包生成器排除依赖、构建产物、运行数据和密钥。SSH 使用部署环境的连接工具；现场部署结果和凭证存放位置在仓库外维护。
