# 插件职责与耦合检查

本次检查以 34 个官方插件、共享库、Spec、Kernel、Control 和 CLI 的实际实现为依据。

| 组件 | 拥有的职责 | 协作边界 |
| --- | --- | --- |
| Kernel / Runtime / Engine | 依赖、权限、生命周期、不可变执行图与运行时 | 不引入 AI、账本、支付领域契约 |
| Control / CLI | 配置、安装、版本锁、发布与回滚 | 共享安装解析器；打包文件操作与管理路由分开 |
| Console | 布局、导航、公开门户、初始化和管理界面装配 | 通过公开 HTTP API 管理其他插件，不保存其业务事实 |
| Users / Auth | 用户资料与偏好 / 密码、会话、密钥及认证 | Auth 单向必需依赖用户能力；Users 只可选调用近期管理员认证 |
| Mailer / Turnstile | 邮件发送 / 验证码验证 | 独立可替换服务，设置入口可以聚合，后端不必合并 |
| AI Router | 模型目录、渠道图、路由与上游编排 | 可选组合协议适配器、BYOK、Auto Router、TPS；不拥有用户凭证库 |
| Auto Router / Token Speed / Rate Limit | 决策与思考强度 / 单请求输出节拍 / 请求与带宽配额 | 独立策略，不把模型输出 TPS 与 RPM/TPM 配额混为一个状态机 |
| 入口与上游适配器 | 客户端解码编码 / 服务商请求响应 | 通过 AI 公共中间表示组合，协议纯工具共享，运行服务分开 |
| BYOK | 用户凭证、个人渠道与密钥解析 | 通过路由/模型目录能力协作，不读取 Auth/Router 的数据库 |
| Billing / Commerce | 余额、账本与请求结算 / 商品、订单、订阅与权益 | Commerce 必需调用记账能力；支付事实不使用易丢的普通 Event 作为确认依据 |
| Stripe / Epay | 平台签名、Checkout、回调及支付状态归一化 | 回调通过 Commerce 能力入账，不直接修改 Billing 的表 |
| Observability / Leaderboard | 请求观测与排名聚合 / 用户和模型榜展示 | 排名使用观测、用户目录和公开模型能力 |
| Model Catalog / Playground | 公开目录展示 / 已认证对话 | 相同模型源的不同访问范围与用户界面，保留独立插件 |
| Tickets | 用户工单、客服回复和状态 | 依赖用户查询；只用纯会话权限检查，不引入近期认证服务依赖 |
| Protocol Converter / Workflow | 旧扩展能力的兼容支持 | 作为可选插件保留，默认渠道图不要求安装这两个旧服务 |

没有发现需要将上述业务插件强行合并或继续拆成更小服务的依据。纯工具、存储助手、UI 基础组件可以共享；业务所有权和数据库保持各自维护。

## 本次调整

1. 将通用管理员会话检查从近期身份认证检查中分离，工单只引用所需部分。
2. 将 Control 的安全解包、哈希、复制和打包从管理路由拆出；安装依赖解析由 CLI/管理 API 共用。
3. 补充命名实现依赖的 SemVer 约束、精确安装锁、启动与在线升级校验。
4. 将单包安装改为必需依赖闭包安装，增加只读预览、逐插件权限、清单指纹、一次图发布及失败回滚。
5. 修正 CLI 能力调用忽略 bindings、会隐式启动已停用可选插件的问题；加入命名依赖的闭包。
6. 修正公共包打包时写死版本号的问题，按实际包版本生成产物锁清单；收紧官方宿主兼容范围。
7. 在现有私有导入边界检查中增加编译产物的依赖声明与包版本检查，避免共享辅助函数产生的隐藏依赖漏检。

详细安装规则和操作方式见 [插件依赖与安装](PLUGIN_DEPENDENCIES.md)。历史开发目录不会自动补哈希锁；远程市场、自动升级、依赖自动卸载不在本次实现范围。
