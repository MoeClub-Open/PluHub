# 在线插件注册源与更新

管理后台「插件」→「在线安装」可浏览目录、筛选分类和注册源、选定版本，审核依赖和权限后安装。进入插件管理时自动检查各已启用的注册源，可用且兼容的新版本会显示在插件列表，并提供「更新」入口；也可点击「检查更新」重新检查。注册源不可用时显示失败提示，不能将检查失败视为没有更新。仅配置内置目录时显示提示：内置目录是镜像快照，需要配置在线注册源才能发现该快照之后发布的版本。更新仍需审核安装计划。管理员须完成近期身份确认，API Key 不能操作注册源或插件生命周期。

## 发布注册源

构建后运行 pnpm pack:all，生成 output/registry/index.json 和 packages/*.tgz。把整个 registry 目录部署到 HTTPS 静态服务即可作为官方或第三方注册源。

官方包使用固定归档时间戳；发布目录的文件名包含压缩包内容 hash，避免 CDN 缓存与目录校验值不一致。

运行中的宿主也公开只读发布端点：
- /registry/v1/index.json
- /registry/v1/packages/<文件名>.tgz

此端点只发布镜像自带的公开官方产物，不发布第三方安装包、运行配置、凭证或数据。

默认官方来源可使用当前版本附带的发布快照，提供可复现的初始安装。独立的 [PluHub 发布目录](https://moeclub-open.github.io/PluHub/registry/index.json) 通过后台「在线安装」→「管理注册源」添加，注册源 ID 可填写 `pluhub-releases`；它由发布流程在验证成功后更新，不依赖运行中的网关镜像。第三方来源也可在后台增删、启停；official 是保留 ID，不允许第三方伪装。第三方与官方均需管理员显式信任和授权。

目录协议：

    {
      "schemaVersion": 1,
      "plugins": [{
        "manifest": { "...": "完整插件 Manifest" },
        "archive": "packages/example.hello-1.0.0.tgz",
        "sha256": "<压缩包 SHA-256>"
      }]
    }

archive 可以是相对目录 URL 或 HTTPS URL。相同 ID 和版本在单个目录内必须唯一。注册源按「官方→管理员配置顺序」为缺少的依赖选择来源，不因来源故障自动切换根插件。可在确认计划查看每个包的来源、版本和权限；只有批准的计划 fingerprint 仍一致才安装。

## 依赖、完整性与更新

安装自动补齐必需插件及 Capability 的唯一实现，遵守版本范围、绑定、禁用状态和依赖环检查。可选依赖不会自动安装；已安装的冲突依赖不会静默升级或启用。所有新包都需授权，并锁定版本、解包内容 hash、来源和压缩包 hash。注册源更新不改变已安装版本。

下载使用 HTTPS、公网地址校验与 DNS 固定，每次重定向重新校验。私网服务须逐个来源明确允许；HTTP 仅限明确允许的本地回环测试源。目录限制 2 MiB/512 项，单包 64 MiB，依赖集合 32 版本/256 MiB；缓存按 hash 校验，清理超过 7 天未使用的条目，达到缓存上限时拒绝继续下载。

原生插件是宿主可信代码；hash 校验用于验证产物一致性，不代替发布者身份信任或系统沙箱。目录 hash 与包同时被发布者替换时，须由来源的 HTTPS 信任与管理员审核保障。

可安全并行替换、能力集合不变且不引入新依赖的插件支持热更新，旧请求使用原执行图并排空。其余插件在线下载、审核和暂存后，在后台「应用更新并重启」。更新只接受更高版本，不允许同版本替换不同代码。重启前保存旧配置和受影响插件数据；失败恢复旧版本与数据，进程中断时下次启动恢复。一次只处理一个待应用任务。

备份含敏感数据，位于配置目录的 .pluhub/update-backups，应纳入主机访问控制和备份保留策略。回滚仅覆盖宿主配置及插件数据，第三方插件若自行修改外部系统，需要自行提供补偿方案。

本地开发仍保留 CLI/管理 API 的本地包安装方式。
