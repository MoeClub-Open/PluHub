# 实现范围与生产适用边界

PluHub 当前为可运行 Alpha，正式运行目标是 Linux x64、Bun 1.4.3。默认单节点，业务插件使用各自的 SQLite 数据库，内存维护部分限流、并发和输出节拍状态。它已经具备账号、网关和商业闭环，但不能等同于多节点高可用商业平台。

当前 35 个官方插件全部预装，新站默认启用 18 个基础插件，包括标准入口所必需的请求限流。计费、支付、个人渠道、订阅上游、自动路由、输出节拍、邮件、验证码、工单和排行榜按需启用。已存在的部署不自动开启这些业务功能；标准 AI 入口的限流依赖由离线升级迁移启用。

## 与成熟生产系统相比仍有的缺口

以下是当前实现边界，按业务需要补充，不作为默认开发排期。

| 能力             | 当前已有                                         | 缺口及适用影响                                                                                                                 |
| ---------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 通用渠道可靠性   | 优先级、会话选择、订阅账号额度冷却和有限安全切换 | 个人流程支持显式配置到平台分组的安全备用出口；普通平台渠道仍无通用健康探测、故障熔断及跨渠道自动切换；上游失败可能直接影响请求 |
| 消费预算         | 余额预留、输出预算和密钥请求数限制               | 缺少按密钥/用户/项目的日月消费预算，以及绝对单请求金额上限；估算预留不能保证最终金额不超预留                                   |
| 监测与处置       | 请求记录、运行日志、磁盘和插件状态               | 缺少标准监测指标导出、跨服务追踪、告警规则及通知闭环；健康探针不能验证真实提供商或支付可用性                                   |
| 商品权益         | 商品、订单、周期余额发放、分组授权               | 商品或订阅尚未自动授予或回收使用分组；购买订阅不等于自动获得模型权限                                                           |
| 团队与管理员权限 | 管理员/普通用户、组织归属和部分组织可见范围      | 缺少按功能细分的管理角色、团队预算和企业统一登录                                                                               |
| 成本核算         | 用户资金账本、请求估价、支付退款和争议调整       | 尚无提供商账单导入、上游成本对账及利润核算；客户扣费不等于服务商真实成本                                                       |
| 备份与发布保障   | 本地加密备份、恢复检查、版本组合和构建检查       | 异地副本、备份失败告警、恢复时限和更严格的发布门禁仍需配置或建设                                                               |
| 多节点运行       | 单节点 SQLite、部分持久账号状态                  | 缺少共享限流/租约、一致配置分发、数据库高可用及调度；不能直接扩多个副本共享一个数据卷                                          |
| 扩展治理         | 可信插件权限和依赖检查                           | 不提供不可信插件沙箱；缓存、内容策略及更多协议按实际需求扩展                                                                   |

不应把已有的退款处理、账本、审计、备份或持续集成写成缺失。订阅账号池已具备提供商内的有限恢复能力，但这也不代表所有渠道具备自动容灾。

## 验收与交付依据

发布组合由 `ci/companions.json` 固定，插件及公共包版本以各包声明为准。构建入口为 `pnpm build:all`，职责和声明检查入口为 `node scripts/check-boundaries.mjs`。针对资金、权限及迁移的变化应做最小必要验证；真实上游、邮件和支付验证须单独使用有效配置与明确预算，见 [联调说明](LIVE_TESTING.md)。

本地模拟、单一提供商成功或健康探针通过，只证明相应范围。上游兼容范围以 [协议矩阵](PROTOCOLS.md) 为准。发布结果、现场凭证、截图和开发过程记录保存在仓库外，不作为产品文档持续累积。
