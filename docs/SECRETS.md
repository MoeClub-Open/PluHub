# 凭据与参数

模型、提示词、图片尺寸、视频时长等业务参数通过请求体或插件配置传递。网页使用当前登录会话；Codex、Claude、Antigravity 与 Grok 的授权由各自的订阅账号管理。正常使用不需要配置密钥环境变量。

## 页面填写

平台渠道在「调用上游」节点直接填写 API Key，每行一把。保存后宿主加密保存，渠道与上游适配器配置只保留 `secret:` 编号；重新打开时不回显密钥，留空保留原值，填写新值后替换。高级接口的 Header 可使用 `{key}` 引用所选凭据，不需要把认证信息再写一遍。

自动路由的决策模型、邮件密码和人机验证 Secret Key 使用同一种输入与保存流程。Stripe、易支付保留其现有的加密凭据和轮换功能。个人渠道凭据仍由 BYOK 管理，订阅授权仍由相应订阅插件管理。

## 保存与权限

宿主在保存管理配置前，将插件声明的 `secretRefs` 中直接填写的密钥转换为凭据编号，并同步替换配置内对这些值的引用。普通配置 API 不返回凭据明文。上游通过原有 `Host.secret(reference)` 读取，`secrets.read` 权限和 `secretRefs` 授权继续共同生效；媒体上游与文本上游分别获得其需要的授权。

通用凭据保存在宿主数据目录的 `secrets.json`，使用 AES-256-GCM 加密，凭据编号作为认证附加数据；对应的 `secrets.key` 为独立生成的 32 字节密钥。文件权限为 0600，更新采用原子替换。明文不会进入普通配置，已登记凭据会参与运行日志脱敏。

替换凭据产生新的编号，进行中的旧配置快照可以完成原请求。旧加密记录随数据备份保留，不在配置写入时删除，避免影响进行中的调用与恢复。

## 升级已有部署

Docker 在独占数据锁内、插件启动前，自动把旧配置中的 `env:NAME` 引用导入加密存储并改为 `secret:NAME`。此前未提供的环境变量不会被虚构成有效密钥；这类引用在实际使用前仍需重新填写。

迁移保留 `.before-managed-secrets` 配置副本，以及只包含旧变量名称和导入数量的 `.managed-secrets.json` 记录。导入的变量从应用子进程环境中移除；部署方应据该记录移除 Compose 和环境文件里的旧密钥项，再重建容器。没有新建渠道、模型或余额记录。

源码部署在停机并备份后执行，省略 `--write` 只查看引用数量：

```sh
bun scripts/migrate-managed-secrets.ts /path/pluhub.json --write
```

备份和恢复必须同时包含普通配置、完整数据目录、`secrets.json` 与 `secrets.key`。仅恢复配置或仅恢复密文不能恢复凭据。回滚至旧版时恢复匹配的数据与部署配置，避免旧版读取新编号。
