# 渠道流程图与模型重定向

渠道只有一种资源形式：名称、启用状态和流程图。协议、地址和密钥引用属于图中的「调用上游」节点；自动路由是一个节点，不是渠道类型。一个渠道可在不同分支使用不同协议与模型；单个调用节点也可通过接口组合，按入口协议与上游模型选择 Chat、Responses、Messages 或 Gemini 接口，设置各接口的路径、认证、请求头与扩展参数。接口组合不增加渠道类型，规则未匹配时明确拒绝。通用 Kernel 和 Engine 不引入 AI 领域类型。

## 操作

1. 在「渠道与路由」创建渠道，自动进入流程图。新渠道先停用，避免未完成的配置对外接收调用。
2. 点击「调用上游」节点，配置协议、Base URL、API Key（直接填写，加密保存）。模型统一在渠道的「提供模型」管理：选择上游节点，配置公开名与该节点的实际上游目标。调用节点显示对应关系，不再重复编辑固定模型和映射列表。
3. 添加请求限流、提示词、思考强度、预算、TPS 或条件分支，拖动端口建立连线。新增节点保持独立，不改变现有路径；删除节点会断开相关连线，不自动绕过被删除的功能。自动路由节点内可直接编辑可复用策略。
4. 在编辑器顶部勾选「启用渠道」，保存流程。后台先验证 Schema、依赖、图结构和目标模型。保存失败不影响上一配置。
5. 在渠道内打开「提供模型」，手动配置或从指定上游节点导入需要提供的模型，再到外部「模型定价」设置价格。模型启停、名称、能力和映射在渠道内管理，外部只编辑价格。在 Playground 调用，或在渠道列表发送测试请求。路径预览执行当前草稿的条件与变换，不必先保存，不调用上游或远程决策器；预览通过不代表已验证提供商连接。

| 节点                           | 作用                                                                       |
| ------------------------------ | -------------------------------------------------------------------------- |
| 请求入口                       | 唯一执行入口                                                               |
| 参数值                         | 提供明确类型的值，可供多个兼容的参数输入引用                               |
| 比较 / 逻辑运算                | 比较数据，或组合、取反布尔条件，输出布尔值                                 |
| 分支                           | 根据布尔输入选择「是」或「否」执行路径                                     |
| 文本内容 / 文本模板 / 文本替换 | 提供文本、插入具名变量，或按字面内容替换文本                               |
| LLM 请求                       | 调用可访问的模型，输出生成文本                                             |
| Jev 请求                       | 使用已配置的 Jev 模型处理状态和问题，输出答案                              |
| 返回内容                       | 将输入文本作为流程的最终回答                                               |
| 系统提示词                     | 在既有消息前插入系统消息                                                   |
| 思考强度                       | 设置标准 reasoning effort，最终适配器仍检查兼容性                          |
| 输出预算                       | 设置输出上限，保留已有较小上限                                             |
| 请求限流                       | 按经过的渠道节点限制 RPM、TPM、并发与响应字节速度；需要请求限流插件        |
| 输出 TPS                       | 限制单请求交付速度，需要 Token Speed，取最严格的速度                       |
| 调用上游                       | 配置协议、地址和密钥引用；支持标准 API 和订阅接入                          |
| 平台分组                       | 个人流程引用有权访问的平台分组，按平台价格结算；可作为明确拒绝后的备用出口 |
| 自动路由                       | 选择已保存的决策策略；`$model` 表示使用模型映射中的策略 ID                 |
| 转到其他模型                   | 委托给其他公开模型及其渠道流程，选择显式/隐式重定向                        |

每个图最多 128 个节点，拒绝重复 ID、缺失连接、循环和不可达的执行节点。数据节点通过数据线参与流程，不需要接入请求路径。跨渠道与自动选择链最多 32 跳，调用前检测循环。自动路由候选最终须到达上游调用节点，候选本身的条件与功能节点也会执行。

### 画布交互与连线

左键在空白处拖动框选，按 Shift、Ctrl 或 Cmd 可追加选择；拖动节点标题可整组移动。空格加拖动、中键或右键拖动平移画布，滚轮缩放。有设置的节点可双击标题展开或收起；请求入口只提供数据和执行端口，不显示空的展开按钮。新加节点直接展开设置，比较、逻辑运算和分支的输入端口在收起时也会显示。

| 操作                 | 快捷键                                         |
| -------------------- | ---------------------------------------------- |
| 撤销 / 重做          | Ctrl/Cmd+Z / Ctrl/Cmd+Shift+Z；Ctrl+Y 也可重做 |
| 保存                 | Ctrl/Cmd+S                                     |
| 全选 / 取消选择      | Ctrl/Cmd+A / Escape                            |
| 复制 / 剪切 / 粘贴   | Ctrl/Cmd+C / X / V                             |
| 复制选中节点         | Ctrl/Cmd+D                                     |
| 删除选择的节点或连线 | Delete / Backspace                             |

快捷键在编辑器内生效；输入框保留文本编辑的撤销、选择和复制粘贴。批量移动、复制、粘贴或删除作为一次图编辑记录，可整体撤销。复制子图保留内部连线，断开指向原图的线；粘贴落在鼠标位置附近。请求入口不能复制或删除。

「分支」节点分别提供「是」「否」出口，单次请求只走其中一条路径；条件输入必须连接独立节点的布尔输出，判断规则可以复用或组合。需要固定选择某条路径时，可连接布尔类型的「参数值」节点。旧「请求条件」在离线配置升级、个人渠道数据库升级或导入旧剪贴板内容时，迁移为「请求入口 → 比较」数据连线；更早的条件分支同时拆成「比较」与「分支」，保留原有路径和结果连线。正常执行和新配置只使用迁移后的格式；非容器部署应先运行离线迁移再启动新版本。不同路径可以汇入同一节点，输入端不限一条线。普通出口和每个分支出口只连接一个后继节点，再次拖线不会覆盖旧连接；需要改接时拖动现有连线端点，或先删除旧线。个人渠道的「失败后」出口可直接连到平台分组。

### 比较与布尔条件

「请求入口」直接输出任务字符数、模型 ID、入口协议、工具和流式标志。将「任务字符数」连接到「比较」左值，选择「大于」，右值填入阈值，例如 `1000`；结果是明确的布尔值，可连接「分支」条件、逻辑运算或多个使用方。工具和流式标志本身就是布尔值，可直接接到分支，无需专用条件节点。

比较支持数值的等于、不等于、大于、大于或等于、小于、小于或等于；文本支持等于、不等于和通配规则匹配；布尔值支持等于和不等于。第一次连入比较节点时，会按来源自动选择数值、文本或布尔类型；整数可直接输入数值比较。已有另一输入连接时保留类型，避免破坏现有连线。未连接的操作数可直接在节点内填写。比较负责输出结果，逻辑运算负责且、或、非，分支只负责选择执行路径。

### 多个上游与模型映射

例如，同一渠道向外提供 `assistant`，带工具的请求走节点 `tools`，其余请求走节点 `plain`，两个节点可以使用不同的模型名：

```json
[
  { "id": "tools", "type": "provider", "modelMap": { "assistant": "vendor-tool-model" } },
  { "id": "plain", "type": "provider", "modelMap": { "assistant": "vendor-chat-model" } }
]
```

连接配置分别保存在两个节点的 `upstream` 中，条件和连线仍由流程图明确配置。对外模型记录的 `model` 为渠道模型 ID；已有隐式模型或固定 `model` 在升级时展开为节点自己的 `modelMap`，保留原有目标。新节点从空映射开始，不继承其他节点的模型；更换协议会清空该节点的旧映射。`modelMap` 与固定 `model` 互斥；空映射表示该节点不接受任何模型。逐模型映射也提供对象类型的参数输入，只允许受控的静态数据来源，不能让请求正文指定任意上游映射。

从「提供模型」为一个节点导入模型，会只更新该节点的对应映射，并保留既有提供模型和价格。调整另一个节点不会覆盖前一个节点的目标，也不会自动给它添加渠道的其他模型。节点摘要只显示自己已声明的映射；未声明的模型不会传给该上游。订阅账号节点保存新映射或变更连接时，会校验目标是否在该节点所选账号的模型目录中；原有映射和连接未变时，编辑价格等无关设置不重复查询目录。模型目录相同仅表示名称相同，不表示两个上游具有相同能力；管理员应为对外提供的模型填写共同支持的能力。

### 参数输入

参数旁的端口显示数据类型，与请求路径端口分别连线。添加「参数值」节点并选择整数、数字、文本、布尔、文本列表、对象、JSON 或密钥，再从其输出拖线到兼容的参数输入；一个输出可以连接多个输入，一个输入只接受一个来源。整数可连接数字输入；JSON 输入可接受非密钥的 JSON 值。请求入口也提供模型 ID、入口协议、流式状态、工具状态、任务字符数、最近一条用户文本及完整会话等数据输出。

连线时使用外部值，原字段暂不可编辑；断开后恢复原字段值。参数值也可连接另一个参数值节点。画布和保存校验都会拒绝类型不符、缺少来源或形成数据依赖循环的连线；删除节点时清理其数据线，复制子图时只保留选中节点之间的线。

上游连接、凭据、分组与限流等参数需要受控的已配置值，不能直接或经中间节点使用客户端请求字段。动态选择模型时，必须在节点中配置允许的模型范围；不能将任意模型输出当作上游地址或凭据。平台管理员流程中预先配置的目标可由入口模型受托访问，个人流程中的模型仍须满足 Key 模型授权；两者都要通过渠道和分组权限检查。密钥类型使用宿主加密保存及适配器授权，个人渠道继续使用自己的凭据与模型范围。执行前按最终参数重新校验连接和计费；预览不会调用上游。接口规则新增、删除和排序会同步调整参数线，存在接口参数线时需先断线再整体编辑其 JSON。

例如，新增一个整数参数值 `60`，将它的输出分别连接到「请求限流」的「每分钟请求」和「最大并发」，这两个参数就共用该值；原请求路径仍需连接到限流节点。

对应的流程数据如下；`next` 控制请求路径，`bindings` 保存参数线，二者互不替代：

```json
{
  "entry": "start",
  "nodes": [
    { "id": "start", "type": "start", "next": "limit" },
    {
      "id": "limit",
      "type": "rateLimit",
      "rule": { "rpm": 20 },
      "next": "call"
    },
    { "id": "call", "type": "provider" },
    { "id": "shared", "type": "value", "valueType": "integer", "value": 60 }
  ],
  "bindings": [
    {
      "source": "shared",
      "output": "value",
      "target": "limit",
      "input": "rule.rpm"
    },
    {
      "source": "shared",
      "output": "value",
      "target": "limit",
      "input": "rule.concurrency"
    }
  ]
}
```

执行时两项限制均为 `60`；断开第一条参数线后，每分钟请求恢复为原先填写的 `20`。可用类型为 `integer`、`number`、`string`、`boolean`、`string[]`、`object`、`json` 和 `secret`。密钥节点使用 `secretRef` 保存加密引用，不使用普通 `value` 字段。

### 文本与模型调用

「文本内容」提供一段可复用内容。「文本模板」在模板中使用如 `{{question}}` 的变量，为每个变量填写文本或连接数据输入；变量名以英文字母或下划线开头，后续可包含字母、数字或下划线，最长 64 个字符。变量按字面内容插入，不执行脚本。「文本替换」按字面查找和替换，可选择只替换第一处或全部替换。

「LLM 请求」选择已配置的公开模型，可使用原会话，设置系统提示词、附加提示词和输出预算；选择替换对话时，以提供的提示词作为新输入。请求协议可使用自动选择、OpenAI Chat、OpenAI Responses 或 Anthropic Messages。输出文本可供后续节点使用。「Jev 请求」使用已配置的 Jev 模型，接收状态和按问题 ID 组织的原生问题，输出答案；单选问题也可以将选项结果接到比较节点。请求节点按需执行：只有到达的执行路径需要它的输出时才会发起调用，同一数据节点在一次流程中只执行一次。互不依赖且同时需要的请求可并发，后续节点等待其依赖完成。

例如，分别将两个 LLM 请求的文本接到同一文本模板的两个变量，再将模板输出连接到第三个 LLM 请求的提示词，最后把第三个模型的文本连接到「返回内容」，即可先并行生成两份回答，再汇总返回。若只需润色，保留一个初答模型和一个润色模型即可。文本替换和输出 TPS 可用于整理结果和控制交付速度，但不会改变上游模型的能力或保证生成质量。

LLM 数据节点先等待完整文本再交给依赖它的节点；因此汇总、润色等流程会在前序调用完成后才开始返回最终文本。请求流式输出时，最终结果仍使用客户端所选协议的流式格式，并可应用输出 TPS。只要流程图包含「返回内容」节点，就只接受纯文本请求；工具调用、图片或结构化输出请求会在内部付费调用前拒绝，即使另一分支连接上游。需要这些能力时应使用不含该节点、能够保留请求语义的上游路径。

### 流程模板

画布中的「流程模板」提供 LLM 智能路由、Jev 智能路由、多模型讨论与汇总、回答润色，以及提示词、内容替换与限速。选择模板后，为各角色选择有权访问的公开模型；内容替换模板还需要填写查找和替换文本。应用模板会替换当前草稿，可使用撤销恢复。保存前可继续调整节点、提示词、阈值和连线，再通过测试请求验证。

### 回答风格与特定问题转路示例

以下组合可以让 DeepSeek 的回答遵循指定的表达要求，并将特定问题交给另一个模型。先配置好 DeepSeek、润色模型和备用模型的公开模型映射及价格，再在流程中连接：

1. 将「请求入口」的最近用户文本连接到「比较」的左值，比较方式选择文本匹配，右值填写例如 `*紧急法律问题*`。将比较结果连接到「分支」的条件输入。
2. 分支「是」连接「转到其他模型」，选择事先配置的备用公开模型；「否」连接「输出 TPS」，再连接「返回内容」。
3. 添加一个 LLM 请求，模型选 DeepSeek，系统提示词填写所需的表达要求，例如「先直接回答，再解释依据；不确定时说明，不编造事实」。默认保留用户的完整会话。
4. 添加文本模板，将 DeepSeek 的文本连接到变量 `answer`。模板例如：`请检查并润色以下回答，保留事实与原意，直接输出修改后的回答：\n{{answer}}`。将模板输出连接到第二个 LLM 请求的提示词；该请求选择润色模型，并使用追加提示词以保留原会话。
5. 如需固定的文字替换，把润色结果连接到「文本替换」，填写要查找和替换的文字，再连接到「返回内容」。无需固定替换时可直接连接润色结果。输出 TPS 控制最终交付速度。

关键词匹配是字面匹配，规则区分大小写，`*` 表示任意字符；需要按语义识别的问题可用 LLM 或 Jev 判断节点替换比较节点。系统提示词和润色可以调整表达，但不能保证 DeepSeek 具有另一个模型的知识、推理能力或完全相同的表现。普通分支会产生初答和润色两笔模型调用；特定问题分支只调用选定的备用模型。包含「返回内容」的图仅支持纯文本请求，工具、图片和结构化输出会在付费调用前拒绝。

### 配置 Jev

在平台渠道的「调用上游」节点，或个人渠道的上游设置中，选择 `Jev / System One`，填写服务地址和 API Key，再创建该服务的公开模型映射及价格。System One 不提供普通聊天测试或模型目录接口，需要通过 Jev 工作流节点进行实际请求验证。

Jev 节点的状态可以是文本、数组或对象；问题以 ID 为键，每个问题设置 `type`、`instructions` 和该类型需要的 `criteria`。例如，下面的单选问题可供分支判断；节点的答案 ID 填 `route`，再将选项输出连接到比较节点：

```json
{
  "route": {
    "type": "choice",
    "instructions": "判断问题是否需要复杂推理。",
    "criteria": {
      "simple": "简单直接的问题",
      "complex": "需要多步推理或深入分析的问题"
    }
  }
}
```

除了单选，还可使用 System One 的 `score`、`noul` 和 `box` 问题。状态、问题和附件会发送给所选上游；请选择适合处理这些内容的服务。

### 内部调用、费用与限流

流程中的每次 LLM 或 Jev 请求都是独立调用，分别检查目标、预留余额、按该模型价格结算，并在调用记录中关联外层请求和节点。平台渠道费用从平台余额扣除；个人自带凭据渠道按既有规则由用户与上游结算。多模型讨论和润色会产生多次费用；即使后续步骤失败，已完成的调用仍会结算。结果不明或缺少可靠用量时按该次预扣金额直接结算，不按零用量处理。

外层协调请求按用户及 API Key 各计一次请求并占用一个并发名额；内部模型调用不重复占用其请求数和并发名额，但各自计入 Token 限额并执行渠道限流。纯文本返回路径的流程出口也会执行其渠道限流。动态分支可能先发生内部调用，再在后续路径遇到限流拒绝；此前已产生的费用不会因此撤销。

### 模型条件

将「请求入口」的「请求模型 ID」或「映射后的模型 ID」连接到「比较」的左值，选择文本的「匹配规则」，填写模型规则，再把比较结果连接到「分支」的布尔输入。前者指本次路由入口请求的模型名，在当前渠道的重定向过程中保持不变；后者是进入当前渠道时模型映射中的上游模型 ID，不是后续调用节点单独覆盖的模型。平台分组委托或独立路由决策会建立新的路由入口。

每行填写一个规则，任意规则匹配即走「是」，否则走「否」。匹配区分大小写，支持精确 ID 和 `*` 通配，例如 `gpt-*`、`claude-*-sonnet*`；没有其他通配语法。预览会带入所选映射的公开名与上游模型 ID，与实际调用一致。仅依赖模型 ID 的分支可在无消息正文时试算费用；依赖正文、工具或流式状态的分支仍需完整请求。

认证、API Key 模型范围、计费和全局限流始终生效。BYOK 必须属于当前用户，并匹配最终渠道 ID。费用按最终模型映射价格结算，日志只记录路径和选型，不记录提示词正文。请求使用配置快照，保存新图不改变已准备好的计划。

渠道级功能统一在流程图内配置，不另设限流、TPS 或路由策略页签。管理员从「模型服务 → 全局限制」设置跨渠道的用户、API Key、响应带宽限制与默认 TPS；渠道节点不能关闭用户、Key 和带宽限制。自动路由节点内编辑共享策略。限流和默认速度的旧设置链接进入全局限制，自动路由链接进入对应渠道的策略配置。流程图地址包含渠道 ID，刷新后仍打开该渠道。支付、账号验证、订阅凭证等资源管理保持各自入口。

请求限流只对实际经过的分支生效，跨渠道重定向保留前序节点规则。入口先对全局用户与密钥限制做只读检查，避免超限后调用决策器。完整计划中的配额在准入时一起检查和预留；失败不消耗其他规则的额度。流结束、取消或错误均释放并发；有完整 Usage 时归还多预留的 Token，执行前失败归还全部 Token，无 Usage 的已开始请求保守保留预留额。窗口按自然分钟重置。限流状态位于单个宿主内存，重启后清空，不提供多副本共享配额。

TPS 节点支持单请求速度、可选的同渠道模型总速度和模型匹配；管理员可选已配置的自定义分词器。旧逐模型覆盖规则迁入节点，保留对默认值的覆盖行为；个人渠道不能关闭平台默认限速。它控制客户端接收的文本、可见思考和工具字段的交付速度，不控制服务商内部生成速度；隐藏思考用量不追加收尾等待，用量和结束帧直接传递。完整用量仍用于计费和调用记录中的输出 TPS 统计。输出节拍统一使用 `ai.output-pace@2`，旧 `@1` 绑定在离线迁移时更新；请求限流插件提供 `ai.request-limits@1`。引用节点但依赖不可用时拒绝保存或调用。

## 配置

`official.ai-router` 配置中所有渠道采用相同结构：

```json
{
  "upstreams": {
    "primary": {
      "name": "主渠道",
      "flow": {
        "entry": "start",
        "nodes": [
          { "id": "start", "type": "start", "next": "prompt" },
          {
            "id": "prompt",
            "type": "prompt",
            "text": "请简洁回答。",
            "next": "call"
          },
          {
            "id": "call",
            "type": "provider",
            "upstream": {
              "protocol": "openai-chat",
              "baseUrl": "https://api.openai.com/v1",
              "keyRef": "secret:OPENAI_API_KEY"
            }
          }
        ]
      }
    }
  },
  "models": {
    "my-assistant": {
      "upstream": "primary",
      "model": "vendor-model",
      "inputPrice": 2,
      "outputPrice": 4
    }
  }
}
```

每个调用上游节点都需要对应适配器和密钥引用授权；控制台保存图时自动同步授权，手工编辑配置需同步适配器 `secretRefs`。图不能执行任意脚本，不支持循环 Agent 或服务端工具执行。

## 旧配置迁移

离线迁移把旧协议字段、`auto-router` 和 `workflow` 渠道持久转换为统一图结构。普通渠道的连接移入上游节点，自动路由移入路由节点；同一旧 workflow 渠道绑定不同流程时拆成对应渠道，保留公开模型别名、价格与重定向。退役插件及能力绑定从配置移除，原配置保存在迁移备份中。

迁移同时把请求限流插件的 `channels` 和 TPS 插件的 `models` 移入所属渠道流程。默认规则、自定义分词器、模型别名和价格保持不变；找不到渠道的旧规则保留供修复。重复迁移不重复添加节点。

原有的条件分支会迁移为「比较」和「分支」两个节点，原分支、参数线和画布位置随之保留；已有独立的「请求条件」会直接替换为同 ID 的比较节点，并补上入口数据连线，原结果线继续使用。平台渠道随既有启动迁移或离线迁移转换，写入前备份配置；个人渠道在 BYOK 插件启动时通过数据库事务转换，失败会回滚并阻止插件启动。升级前仍应备份配置和数据目录。

离线迁移可先预览，再停机写入（写入前生成权限 0600 的原配置备份）：

```sh
bun scripts/migrate-plugin-boundaries.ts /data/pluhub.json
bun scripts/migrate-plugin-boundaries.ts /data/pluhub.json --write
```

## 显式与隐式模型重定向

模型重定向统一在渠道流程内使用「转到其他模型」节点配置；外部模型页只负责定价，没有独立的重定向规则表。节点可直接连接请求入口，也可连接条件分支的出口。

```json
{
  "entry": "start",
  "nodes": [
    { "id": "start", "type": "start", "next": "target" },
    { "id": "target", "type": "upstream", "target": "chat/fast", "mode": "implicit" }
  ]
}
```

- 隐式：内部使用目标模型，响应继续使用客户端请求的模型名；没有目标模型响应头。
- 显式：响应使用配置的目标公开模型名，并返回 `X-PluHub-Model`。选择自动路由目标时返回该虚拟目标别名，实际物理模型仍记录在调用日志。
- 两者都是网关内部重定向，不返回 HTTP 301/302，不把服务商 Base URL 或凭证交给客户端。

目标使用已配置模型的路由 ID。Key 按入口请求的公开模型授权，目标属于管理员预先配置的委托，不要求客户端额外持有内部目标的模型授权；渠道和分组范围继续受密钥约束。运行时拒绝循环和超过 32 层的委托。

升级时，离线配置迁移将启用的旧 `redirects` 转换为目标渠道内的「比较」「分支」和「转到其他模型」节点，并在「提供模型」中保留入口别名及目标的目录信息和价格。比较使用渠道模型 ID 的精确相等，不影响普通模型的原有路径；重定向链折叠到最终目标，保留显式/隐式返回方式。已停用规则不覆盖同名直接模型。迁移完成后移除旧字段，正常配置和执行不再读取它；缺失目标或循环会中止迁移，原文件留在升级备份中。非容器部署应在启动前执行离线配置迁移。

## 验证

主仓 `tests/channel-workflow.test.ts` 覆盖四入口的 JSON/SSE 身份、权限与计价、全协议计划、普通渠道变换、自动路由候选图、BYOK 最终归属、分支上游、持久化与重启、取消、循环、无效更新与快照。插件仓验证迁移、图结构和重定向；包安装验证确认公开发布产物可独立执行。`pnpm demo` 的渠道也已使用统一图结构，只访问本地模拟上游。

个人渠道的「调用上游」可通过 `fallback` 错误边指向 `platform` 终点（`groupId`、可选 `model`）。错误边计入图校验和连线，不能形成环或留下不可达节点。它只在首事件前明确拒绝时执行；细则与计费见 [个人渠道](PERSONAL_CHANNELS.md#平台分组与备用切换)。平台渠道不能通过该节点再次委托分组，避免递归组装与权限绕行。
