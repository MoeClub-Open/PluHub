# ADR 0001：能力依赖、实现约束与安装锁

状态：已实现，兼容 Manifest v1 现有字段。

## 背景

现有 `requires` 只能表达 Capability 主版本，安装器一次只复制一个包。共享辅助函数可能让调用者遗漏能力声明；固定的公共包版本号与验证脚本中的包名阻碍独立发布。

## 决定

1. 继续默认依赖可替换 Capability，不把官方插件 ID 编入 Kernel 或自动安装器。
2. Manifest v1 增加可选 `dependencies: {pluginId: npmSemverRange}`。需要特定实现时才使用；启动、启用、配置和替换均校验。旧 Manifest 不变，Schema 兼容基线保持。
3. 宿主配置项的 `version` 是精确安装锁，配合已有 `integrity`。新包自动生成，旧开发配置仍可省略。显式升级更新锁，不能绕过其他插件的实现约束。
4. 自动解析本地必需依赖；可选依赖不自动拉入。多个实现必须绑定；旧包不暗中升级或启用。权限和配置由安装者分别提供。
5. 包操作、解析/事务和管理路由分开。CLI 与后台共享解析器；先预览指纹，再暂存、校验与启动依赖，最后一次发布执行图。失败只撤销新增实例和代码，保存原图及原配置。
6. 新功能要求宿主 `0.1.0-alpha.2`；产物锁记录各自真实版本和 SHA，支持插件独立版本。

## 未采用的方案

- 将全部能力依赖改为固定官方插件 ID：失去实现替换能力。
- 自动授予所需权限、自动启用或升级现有插件：改变安装者已有授权和部署选择。
- 递归安装所有可选服务：扩大部署并制造可选服务之间的硬循环。
- 首期加入远程市场、自动卸载和任意 npm lifecycle：与本次本地可审查安装目标无关。

## 后续条件

若增加远程目录或市场，沿用同一解析/安装事务与权限边界，另定义下载完整性、索引刷新和来源授权。若 Manifest 依赖语义发生破坏性变化，必须增加协议版本与迁移测试；不能仅扩大宿主 SemVer 范围。
