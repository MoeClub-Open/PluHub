# 个人渠道与 API Key 绑定

普通用户从「个人渠道」添加上游，选择 OpenAI、Anthropic、Gemini、DeepSeek、OpenRouter、New API 或自定义预设，填写地址、密钥和模型映射。预设用于填充可编辑的连接信息，不是渠道类型。每个用户最多保存 64 个渠道，每个渠道最多 256 个模型；渠道可启停、改名、轮换密钥、删除及使用流程图组合功能。

渠道与凭证按用户隔离。上游密钥使用现有 AES-256-GCM Vault 加密，不返回给浏览器；管理写入要求控制台会话。保存采用 revision 检查，拒绝覆盖过期编辑。流程图支持条件、提示词、思考强度、输出预算、TPS、渠道内模型重定向和调用上游；个人流程不能引用平台自动路由策略或注入其他上游连接。

BYOAPI 可粘贴 New API 导出的连接 JSON，或使用 base_url/api_key 等常见属性填充连接。保存前即可获取模型目录，返回结果不包含密钥，只有确认保存后才创建渠道。目录查询沿用公网校验、超时与响应大小上限。

## BYOSUB 自带订阅

「个人渠道 → 自带订阅」管理用户自己的 Codex、Claude、Antigravity 授权。复制授权链接或在新标签页登录，再粘贴完整回调链接完成接入；也可导入单账号授权 JSON。无需配置 OAuth 应用。账号加密存储与刷新由各提供商插件维护，个人渠道只保存绑定引用。个人订阅与管理员的平台订阅账号隔离，双方不能相互引用；管理操作限本人控制台会话，网关 API Key 不能管理授权。

添加授权后点击「添加渠道」，填写模型映射，继续使用同一套流程图、Playground 和 API Key 绑定。订阅授权仅发送到对应提供商的官方上游；兼容网关地址和网关 API Key 应使用 BYOAPI。Codex 默认 CLI 接入，可按实际授权选择 SIWC；CLI 接入拒绝其不支持的输出预算和 temperature，测试调用会省略预算参数。订阅渠道不自动抓取或推测模型权限，模型列表由用户按实际授权填写。

个人订阅支持按需刷新、一次同账号 401 刷新重试、429/额度冷却与并发占用；取消、异常和结束时释放占用。停用或删除授权后，绑定 Key 不回落到平台收费渠道。个人订阅调用保留用量与调用记录，不从平台钱包扣模型费；平台订阅渠道继续按平台规则计费。

个人渠道使用自己的上游授权；平台渠道使用管理员配置的上游授权。平台渠道凭证覆盖功能及其旧接口已移除，升级时清理对应凭证，并停用曾绑定这些凭证的 API Key。

## 原价与消耗倍率

模型 `inputPrice` / `outputPrice` 始终表示原价（USD / 百万 Token）。可填写原价，或点击「匹配平台原价」填入同名模型的已配置原价。此操作仅补空值。

- 自动：分别以 `upstreamInputPrice / inputPrice` 和 `upstreamOutputPrice / outputPrice` 计算消耗倍率。未填写某一侧上游报价时，该侧按原价估算 1×；缺原价时倍率未知。
- 手动：有效输入/输出价格 = 对应原价 × 渠道 `consumptionMultiplier`，允许 0，默认 1。
- 调用成本（USD）= `(输入 Token × 有效输入价 + 输出 Token × 有效输出价) / 1,000,000`。调用日志按微美元四舍五入。原价目录不随倍率变化。
- 原价和有效价均为 0 时倍率显示 1×；原价 0 且上游报价非 0 时倍率显示未知，仍可按报价估算成本。价格缺失不当成免费。

New API 预设可读取公开 `/api/ratio_config`，把上游基础 Token 价格作为报价预览，用户确认应用并保存后生效，保留模型原价。转换规则为 `input = model_ratio × 2`，`output = input × completion_ratio`，不导入按次价格；公开报价不包含用户分组折扣、缓存和特殊服务层费用，可手动覆盖。模型目录同步与价格同步都有超时和响应体大小限制，不自动发起文本生成。

个人渠道成本由用户与上游服务商结算，PluHub 钱包不扣个人上游的模型费用；调用记录中的成本用于估算。平台渠道继续走既有计费规则。

## 密钥与路由

创建或编辑 API Key 时可同时绑定多个平台渠道及自己的个人渠道；不选择时使用「平台默认路由」。个人渠道使用该渠道自己的上游凭证，平台渠道使用管理员配置的授权。修改绑定不需要轮换 Key，下一次请求生效；升级会保留既有单渠道绑定。

迁移先将旧单渠道值写入渠道数组，再删除 `channel_id`、`credential_id`；后续只保存和读取 `channelIds`。密钥配置统一通过 `PUT /keys` 编辑，旧 `/keys/binding` 接口及 `ai.routing@1`、`ai.catalog@1` 入口已移除，不保留双写或运行时回退。

客户端使用标准 `Authorization: Bearer <PluHub Key>`，不需要额外传凭证 ID。未指定渠道时按模型匹配可用绑定，平台渠道优先，同名个人模型按绑定顺序匹配；`x-pluhub-channel` 可显式选择已绑定渠道，不能越过绑定范围。每次请求检查渠道所有权、启停和凭证有效性；Key 的模型允许范围仍按客户端公开模型名检查。绑定渠道不可用时不会扩大到未绑定渠道，个人订阅授权失效也不会自动改走平台收费渠道。已经开始的流按既有排空与取消机制结束。

未绑定的 Key 使用平台路由；显式指定 `x-pluhub-channel` 可选择当前用户的渠道。`/v1/models` 返回绑定渠道的可用模型并按默认匹配顺序去重；模型目录与价格试算使用相同授权范围，价格和倍率以实际匹配的渠道为准。登录后的控制台模型目录与 Playground 默认合并展示平台模型及当前用户可用的个人模型，按渠道保留独立身份与价格。Playground 使用“渠道 ID + 模型 ID”选择并显式发送 `x-pluhub-channel`，同名模型不会覆盖或误用其他渠道；未登录的公开目录只展示平台模型。API Key 的目录和路由仍遵守自身绑定范围，不因控制台模型可见性扩大授权。个人模型不复用平台公开性能统计。同名模型在不同渠道、不同用户之间各自独立。

## 多接口组合

BYOAPI 与平台流程图的上游连接均可配置 `interfaces`。这是同一连接内的有序接口路由，不增加渠道类型。每条规则声明 `incoming` 入口协议、目标 `protocol`，可用 `models` 按映射后的上游模型精确匹配或使用 `*` 通配。配置接口组合后使用第一条匹配规则，没有匹配项时明确拒绝；没有配置组合的连接继续按其默认接口转换请求。

支持 Chat Completions、Responses、Messages 和 Gemini 任意组合。`path` / `streamPath` / `modelsPath` 相对于当前连接的 Base URL，`{model}` 会编码为路径参数；Gemini 普通和流式路径分别处理。每条规则可配置认证方式、请求头和服务商扩展参数。`{key}` 仅引用此连接的密钥，不读取客户端认证；模型、输出预算与用量采集不能被扩展参数覆盖，仍由模型映射与渠道流程决定。订阅账号不允许通过这些设置向任意 API 地址发送 OAuth 凭据。

模型发现按各规则的协议、目录路径和认证查询，并按规则匹配模型，合并重复模型的接口声明。部分接口发现失败仍返回其他接口的结果与对应错误；Chat / Responses 共享相同目录配置时合并查询。模型发现通过各物理适配器的 `ai.upstream-models.<protocol>@1` 能力读取其已授权密钥引用，路由器不直接读取服务商密钥。

个人接口路由始终继承本人渠道的凭据与公网边界，不接受其他渠道连接或凭据覆盖。修改接口组合不合并平台/其他个人渠道的模型映射，也不改变 API Key 的渠道授权。

## 公网连接边界

个人渠道禁止 URL 中的用户名、密码、查询串和片段；默认仅允许公网 HTTP(S)。传输层在实际连接的 DNS 解析中检查所有地址，阻止本机、内网、链路本地、保留地址及 IPv6 过渡/映射地址，不跟随重定向。管理员可通过 BYOK 插件 `allowedPrivateOrigins` 配置精确来源例外，用于受信任私有上游或本地模拟测试。该设置不向用户开放；生产默认无例外。

数据随 `/data` 备份，包括 BYOK SQLite 与 `vault.key`。升级保留个人渠道、自带订阅和对应 Key 的渠道绑定；已删除的平台渠道凭证及其 Key 绑定不再可用。
